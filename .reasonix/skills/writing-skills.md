# 编写技能

## 概述

**编写技能就是将测试驱动开发应用于流程文档。**

**核心原则：** 如果你没有观察到智能体在没有该技能时失败，你就不知道这个技能是否教了正确的东西。

## TDD 映射到技能

| TDD 概念 | 技能创建 |
|----------|---------|
| **测试用例** | 带子智能体的压力场景 |
| **生产代码** | 技能文档（SKILL.md） |
| **测试失败（红）** | 智能体在没有技能时违反规则（基线） |
| **测试通过（绿）** | 智能体在有技能时遵守规则 |
| **重构** | 在保持合规的同时堵住漏洞 |

## 何时创建技能

**创建条件：**
- 技术对你来说不是直觉上显而易见的
- 你发现自己反复解释同一件事
- 存在明确的正确和错误做法
- 可以编写明确的规则

**不创建：**
- 对于琐碎的常识
- 对于你个人偏好的风格
- 作为文档的替代

## 技能结构

一个好的技能包含：
1. **概述** - 一句话说明用途
2. **何时使用** - 明确的条件
3. **规则/步骤** - 可执行的内容
4. **红线** - 禁止事项
5. **示例** - 好与坏的对比
